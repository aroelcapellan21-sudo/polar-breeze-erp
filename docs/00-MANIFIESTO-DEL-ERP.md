# Manifiesto del ERP

Estado:

> Vigente — pendiente de revisión y aprobación formal

Objetivo:

Declarar, en una sola voz y sin el aparato de artículos numerados o listas de campos, qué es este sistema y qué se niega a ser. Donde `01-VISION-ERP.md` explica el contexto de negocio, `02-CONSTITUCION-ERP.md` fija la ley, y `99-FILOSOFIA-DEL-SISTEMA.md` reflexiona sobre el porqué, este manifiesto **afirma**. Es el documento que se lee primero para sentir de qué trata el proyecto, antes de aprender cómo funciona.

Contenido:

El ERP de Flujos Patrimoniales no administra módulos. Administra el patrimonio vivo de una organización. Cada movimiento de capital, mercancía e información forma parte de un ciclo continuo, donde ningún dato existe de manera aislada y ningún cambio ocurre sin dejar evidencia. El sistema no solo informa el estado actual; conserva la historia completa que permitió llegar a ese estado.

## No construimos módulos. Construimos memoria.

Un sistema que solo muestra el saldo de hoy es un sistema que ya olvidó cómo llegamos hasta aquí. Este ERP no acepta esa amnesia. Cada dato creado, modificado, aprobado, anulado o usado deja una huella permanente — no como opción, como condición de existencia (Artículo 30 de `02-CONSTITUCION-ERP.md`). Lo que el sistema no puede reconstruir, el sistema no lo afirma.

## El patrimonio no se opina. Se demuestra.

No hay saldo que valga por sí mismo. Todo capital, toda mercancía, todo estado del negocio es la consecuencia matemática de una historia de eventos — nunca un número que alguien escribió y que hay que creer por confianza. Cuando este sistema dice cuánto hay, puede mostrar exactamente cómo se llegó a esa cifra.

## Tres flujos, un solo patrimonio.

Capital, mercancía e información no son tres sistemas distintos que hay que conectar a la fuerza. Son tres caras de lo mismo: el patrimonio de la empresa moviéndose. Un despacho no es solo un evento de inventario — es, al mismo tiempo, capital comprometido e información que respalda ambos. El sistema los trata siempre como una sola unidad, nunca como módulos que hay que sincronizar después.

## Polar Breeze es la primera empresa, no el límite.

Este ERP nació multiempresa. No fue diseñado para una empresa y adaptado después — fue diseñado para muchas, y Polar Breeze es simplemente la primera en usarlo. Ninguna pantalla, ningún cálculo, ningún reporte asume que existe una sola empresa en el mundo. El crecimiento no es una reescritura futura: es una parametrización que el sistema ya sabe hacer.

## Ningún dato se pierde por falta de señal.

La operación real ocurre en la calle, en el camión, en el cuarto frío — no siempre donde hay conexión. Este sistema captura primero, sincroniza después, y nunca le pide al usuario que elija entre trabajar y perder su trabajo.

## Nada se borra. Todo se corrige hacia adelante.

Un error no se tacha del pasado — se corrige con un evento nuevo que dice la verdad completa: qué se pensó primero, qué se corrigió después, y por qué. La historia de un dato equivocado es, en sí misma, información valiosa que este sistema se niega a destruir.

## La documentación no describe el sistema. Lo autoriza.

Aquí no se escribe código para después explicarlo. Se decide, se documenta, se aprueba, y solo entonces se construye. Un módulo sin documentación aprobada no es un módulo adelantado — es un módulo que no debería existir todavía.

## La IA que participa aquí no está de visita.

Cualquier inteligencia artificial que trabaje en este proyecto —incluida la que redactó estas líneas— está sujeta a las mismas reglas que cualquier persona del equipo: no toca código sin mostrar el plan, no asume donde debería preguntar, y dejará su propia huella permanente en cada decisión automática que tome. La conveniencia de una respuesta rápida nunca vale más que la trazabilidad de cómo se llegó a ella.

## Esto no termina. Se sostiene.

No hay una versión final de este ERP, porque no hay una versión final de una empresa viva. Lo que este sistema promete no es llegar a un estado terminado — es que, en cualquier punto de ese crecimiento, alguien pueda preguntar "¿qué pasó aquí?" y el sistema tenga, siempre, una respuesta completa.

Observaciones:

Este manifiesto no introduce reglas nuevas sobre las ya establecidas en `02-CONSTITUCION-ERP.md`; es su síntesis declarativa. Si en algún punto una frase de este documento pareciera contradecir a la Constitución, la Constitución prevalece (misma jerarquía documental descrita en la Objetivo de ese documento).
